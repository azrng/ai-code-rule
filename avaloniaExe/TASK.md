# 任务清单（TASK）

> 本文件只记录具体任务内容、状态与交付要求。
> 规则解释、阶段门控与工作方式以 `AGENTS.md` 为准。

---

## 使用约定

- 开始任何修改前，先检查是否已有对应任务；有则更新，无则新增。
- 任务状态流转统一使用：`TODO` -> `DOING` -> `REVIEW` -> `DONE`。
- 无法继续推进时，状态改为 `BLOCKED`，并明确阻塞原因与所需条件。
- 新功能开发需标注所处阶段：`阶段 0` / `阶段 1` / `阶段 2` / `阶段 3`。
- 文档、规范、脚手架、流程类任务可使用 `治理` 作为当前阶段。
- 每次开发完成后，需同步更新本文件与 `doc/devlog/`。

---

## 字段说明

| 字段 | 说明 |
| ---- | ---- |
| 任务 ID | 唯一标识，如 `T001` |
| 任务目标 | 本次交付要解决的问题 |
| 当前阶段 | `阶段 0-3` 或 `治理` |
| 负责人 AI | 当前主负责的 AI Agent |
| 任务状态 | `TODO` / `DOING` / `BLOCKED` / `REVIEW` / `DONE` |
| 优先级 | `P0` / `P1` / `P2` / `P3` |
| 最近更新时间 | `YYYY-MM-DD` |

## 维护要求

- 已完成且无需持续跟踪的任务，可仅保留在任务总表中，不强制保留详细卡片。
- `REVIEW` 状态表示已完成开发，等待用户或下一阶段确认。
- `DONE` 状态表示已完成交付并确认闭环。
- 若任务范围扩大，应直接更新原任务详情，不新增语义重复的平行任务。
