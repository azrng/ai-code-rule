关键机制速览（现状）

  • 内容与引擎同版本：内容全量内嵌 exe、同版本构建发布，无独立包与包缓存
  • 更新检查门：仅「无参交互模式」执行一次；--offline / 任何带参命令都不联网
  • latest.json：{ version, engine_sha256 }；engine_version 是旧 2.x 兼容字段，新代码不读
  • 版本比较：x.y.z 语义化；dev 不比任何远端版本新
  • 共享缓存：%LOCALAPPDATA%\use-ai-rule\engine\<版本>\；读时哈希回验、写时 temp + 原子改名
  • 失败哲学：任何失败只降级不阻塞启动；安装成功必退出重跑

现状没有 · 提议差异对照

  • ① 首次启动存全局副本 —— 现状不写任何全局位置（对应提议步骤 1）
  • ② 更新安装同步全局存储 —— 现状只落下载缓存 + 替换本目录 exe 后退出（对应提议步骤 3）
  • ③ 检查失败时查本地更高版本 —— 现状直接降级继续交互（对应提议步骤 4 前半）
  • ④ 多目录旧副本离线升级 —— 现状唯一共享物是下载缓存，且仅「在线 + 已确认」路径读取（对应提议步骤 4 后半）

新增机制（目标态 · A1 已修复：sidecar 架构）

  • 存储：engine\<版本>\ 目录自包含 = exe + meta.json（version + sha256），无中心清单——单文件损坏只丢一个版本，删目录即整体清理，无多实例并发写同一 JSON 冲突
  • N1 自登记：目录在且 sidecar 验证过 → 零成本跳过（常态）；未登记才算自身 SHA-256 + 复制 + 写 sidecar；dev / 不可解析版本不登记
  • N2 本地回退：仅「在线检查失败 / --offline」进入；扫 engine\*\ 读 sidecar，最高版本 > 本机 → exe 哈希回验 → 本地 offer 汇入同一确认链；在线已最新 / 用户拒绝不触发
  • N3 sidecar 写入：自更新字节校验通过后与缓存 exe 同步落盘，同生共死
  • 安装路径全复用：本地 offer 走 TryUpdateEngine 缓存命中分支，免下载直接替换
  • 保留策略：当前版本 + 最高 N 版目录整体清理（sidecar 随目录走），N 待定
  • 待拍板：A2 同版本不同哈希语义 / A3 命令模式是否登记 / A4 清理竞态与离线文案 / B3 --offline 是否触发 N2
