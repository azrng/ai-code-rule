## 修改原因

用户希望「只想要 Vue rule 或 React rule」这类无后端诉求可以直达：此前问答 Q2「后端技术栈」在 Web 形态下只有 .NET / Node 两个选项（选项从候选 Profile 的 traits 推导，而没有任何 `form=web` 的 Profile 带 `backend=none`），裸 React 目录的检测补答同样选不出「无后端」，只能退到 generalProject（含后端规则、非前端专属口径）。html+js 场景已有 staticHtml 承接，本批把它与新组合对齐到同一「纯前端 / 静态站点」家族，并补齐通用前端（技术栈无关）入口。

## 主要修改内容

- 组合接入完全走数据驱动，引擎零改动：问答选项、检测候选过滤、补答、Q5 能力开关、经典大类菜单、配方记录、`--check` 三道校验（traits 文案齐全 / 输出契约一致 / 决策树全路径仿真且全部可达）对新 Profile 自动生效。`general` 是 frontend 维度的新值，`wizard.options.frontend.general` 提供文案后即被校验接受。
- 问答路径：Q1 选「Web 应用」后，Q2 后端选项变为 .NET / 无后端 / Node.js；选「无后端」后 Q3 前端出现 React / Vue / 通用前端。经典路径：技术大类「纯前端 / 静态站点」下可选 staticHtml / reactOnly / reactOnly-ai / vueOnly / vueOnly-ai / generalFrontend。
- 检测策略保持「不隐式补默认」：裸 React 目录（只有 package.json react 依赖）仍为部分结果——form=web、frontend=react 已确认，backend 与 ai-capability 未确认，候选 5 个（含 reactOnly / reactOnly-ai），补答时可选「无后端」；不自动判定 backend=none，避免 monorepo / 分仓场景误锁。
- 根规则按纯前端改写：三阶段（设计文档 → 页面与交互实现 → 验证与交付，对齐 staticHtml 而非全栈四阶段），`target-list` / `subrule-index` 不含 backend-AGENTS.md，契约纠错口径改为「数据口径 / 类型定义」而非前后端契约；能力开关 doc / infra / design-system 均可用（默认启用 = 当前组合），Q5 行为与其他 Profile 一致。
- 复用与新增边界：doc / infra 直接复用 `arch/generalProject/` 通用片段（框架中性），design-system 复用各自栈的既有 yaml；仅 frontend-AGENTS.md 做三个薄变体（必须剥离后端耦合表述），共性「无后端数据口径」抽成 `shared/frontend/no-backend-data.md` 一处维护。共享请求小节 `request-rules.md` 的「后端 API」措辞按泛指远端服务理解，未改动（改动会波及 6 个全栈 Profile 正文）。
- 第二批（1.42.0）AI 变体架构：不复用 .NET 后端口径的 `ai-capability` 模块正文，新增 `ai-capability-frontend` 模块承载浏览器侧口径（接入方式三选一并只选一、密钥红线、`src/ai/` 封装层、流式 / Prompt / 会话 / 降级 / 可选能力分层）；frontend / doc / infra 用 `Subrule.sources` 多源拼接（栈基础文件 + `shared/skeletons/frontend-ai/` 追加段），追加段无 front matter、栈间共享一处维护。问答在 web+none+react（或 vue）候选只剩 AI 分歧时自动出现「是否需要 AI Agent 能力模块」，Q5 中 AI 仍为锁定项——与全栈变体同构，单一事实来源不变。
- 旧 Profile 生成正文零变化：1.41.0 批次对既有 Profile 的 manifest 改动仅涉及向导展示文案（form.web / form.static / backend.none 描述）与家族描述，均不进入生成产物；1.42.0 批次不触碰任何既有 Profile 条目与共享片段。两批唯一产物差异是全量版本行 1.40.0 → 1.42.0。
