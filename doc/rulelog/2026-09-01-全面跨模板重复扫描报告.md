# 2026-09-01 全面跨模板重复扫描报告

## 背景

七轮簇推进式收敛（客户端簇 → 测试/发布段 → ui 规则段 → maui infra/doc → 权限矩阵/common-tasks/flutter）清零已知清单后，本轮改用**系统性全量扫描**：不按簇推进，对全部 20 个 Profile 的 emit 输出做归一化全对比，把漏网的跨模板重复一次找全。

## 方法

1. `use-rule --emit` 全量输出 20 Profile（排除 CLAUDE/GEMINI/GROK 指针桩，其按设计全同）；
2. 按标题/YAML 顶层键切分为 **700 个小节**（≥200 归一化字符）；
3. 归一化：`{{var}}`→占位、平台词（react/vue/wpf/avalonia/maui/flutter/tauri/wails/electron/dotnet 等 40+ 词及 Profile id）→同一占位、数字（版本/日期）→占位、去标点空白；
4. 字符 10-shingle 倒排 + 文档频率过滤（>50 小节命中的公共措辞不参与配对），全对小节算**包含度**（shared / min(|A|,|B|)），阈值 0.60，union-find 聚簇；
5. **片段归因**：`fragments/` 全部源文件建同一归一化索引，小节反查来源；全簇命中同一共享片段 → 判"已收敛"（32 簇，如 kiss ×12、anti-patterns ×12、response-format ×7），多源/未归因 → 进入人工核验（66 簇）；
6. 补充 SHA-256 **整文件字节级**查重。

脚本：`%TEMP%\ai-code-rule-scan\{scan,verify,verify2,verify3}.py`（会话产物，核心参数见上）。

## 排除的假阳性（已核验）

- **root/AGENTS.md 派生段**：纠错与回退机制（20 处）、四个阶段（14 处）、理解检查清单（13 处）、最小充分上下文（7 处）等 1.00 全同段，grep 证实全部来自单一 `fragments/root/AGENTS.md`，根模板本就是单源，**非发现**；
- **manifest 生成段**：子规则索引、目标、技术栈、默认端口等由配方变量驱动，差异来自数据而非片段复制；
- **结构平行段**：如 web 双端的 `state_management`（归一化 0.74），差异是真实框架语义（hooks/zustand vs composition/pinia），收敛价值低。

## 发现（按优先级分层）

### T0 — 整文件字节级全同（7 组）：**复核后判定为已收敛，非发现**

manifest 审计确认全部 7 组均为**单源跨架构引用**的预期结果（2026-08-31 轮已完成的收敛），不构成源重复：

| 组 | 实际来源（manifest） |
|---|---|
| blazor 对 4 文件全同 | `dotnetBlazorWebApp` 的 backend/infra/doc 均指向 `arch/dotnetBlazor/*`，designSystemSource 同 |
| core-single ≡ layered infra | `arch/dotnet-layered/infra-AGENTS.md` 单源 |
| layered ≡ python doc | `arch/dotnet-layered/doc-AGENTS.md` 单源（先例：python→dotnet-layered） |
| react ≡ vue LinkdotNet doc | `arch/reactLinkdotNet/doc-AGENTS.md` 单源 |

> 教训：emit 输出全同 ≠ 源重复，必须先核对 manifest 引用再定性。

### T1 — 共享片段已存在，arch 层仍带本地副本（审计后大幅修正）

初扫估计"约 25 处可机械切换"，**逐对审计后修正**：对全部 shared 片段标题 × arch 本地同名段做系统配对（1163 对），无一达到 ≥0.93 的"可直接 include"级；advisory 系列 11 处已是 include、9 处为有意的领域裁剪变体。真实情况分三层：

- **已收敛（审计排除）**：advisory 系列 11 处、reactWails 路由、doc 契约要求等，emit 命中来自 include 本身；
- **可收敛（句号级/单目录路径级，已执行）**：`dotnet-layered`、`dotnet-core-single` 的数据库迁移规则 vs `shared/backend/db-migration.md`（2026-09-01 轮完成）；
- **真变体（明确不合并）**：blazor 迁移段（`（可选）`标题语义）、react-ai 迁移段（PostgreSQL/SQLite 双工具策略）、flutter 迁移段（drift）、comment-rules 全系（各 arch 层名/IPC/端点/命令 bullet）、exception/docker 各半变体、tauri/python/wails 的 advisory 裁剪、react-ai 全线近变体（0.5–0.86，需"基座+增量"结构单独设计）。

> 附带结构观察：`shared/` 内部存在平行变体（backend/desktop 两份 db-migration、application/backend 两份 comment-rules、doc 三份 stage0-design），系有意拆分但重叠度高（stage0-design 与 -api 约 70% 包含），可考虑"基座 + 增量行"嵌套 include。

### T2 — design-system.yaml 跨模板重复（arch 层 include 采用数为 0）

生成器 include 机制对 design-system.yaml 同样生效（`RuleRenderer.ReadRequired` 统一走 `FragmentExpander`），但 **16 个 yaml 无一处使用**。归一化包含度：

| 小节 | 涉及 Profile | 体量（归一化字符） |
|---|---|---|
| `component_specs` | react / react-ai / vue（642 行结构完全平行，0.995/0.916，差异仅组件库行） | 16.6k ×3，冗余 ~33k |
| `tokens` | react / react-ai / reactWails / staticHtml / vue / vueWails（0.91–0.99）+ avalonia/wpf（0.96，1.5k ×2） | ~12k + ~1.5k |
| `form_rules` | web 5 份（0.94–1.00）+ flutter/maui（0.93） | ~3.2k + 0.5k |
| `page_states` | web 8 份（0.77–1.00）+ 桌面/移动对 | ~2.9k |
| `echarts/charts/chartjs` | web 6 份（0.92） | ~2.9k |
| `do` / `dont` | web 4+4 份（0.85–0.96） | ~2.8k |
| `ant_design` / `element_plus` / `component_rules` / `mvvm` / `resources` / `meta` / `icons` | 各自家族对 | 各 0.4–0.9k |

收敛路径分两类：
- **框架无关小节**（tokens/page_states/form_rules/do/dont/meta/图表规范）→ 直接抽 `shared/design/` + `<!-- include: -->`；
- **component_specs 类**（通用规格 + 少量组件库差异行交织）→ 需拆"共享基座 + 框架增量"两层结构，include 基座、增量留在各 yaml。

### T3 — 跨技术栈近似段（0.6–0.9，掺真差异）——**已系统审计（2026-09-01 第二轮）**

跨 Profile 同名标题段配对（≥0.90）共 14 对，逐对核验后 10 对为 include 组合的预期全同（假阳性）；真实残留已处理：
