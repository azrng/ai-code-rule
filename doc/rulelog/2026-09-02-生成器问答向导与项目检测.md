## 修改原因

原生成器只有「技术大类 → Profile」两级选择，用户需要在 20 个预设里认领自己的项目。新方案改为按用户的母语提问（有无后端、用什么前端、什么桌面壳），结合回答生成规则；并遵循"先检测再问答"：扫描目标项目特征直接给推荐，确认不了再进问答树。自定义选择路径需要留下配方记录（`.ai-rule-profile.json`）便于核对与后续按原配方升级，且该记录自动加入目标项目 `.gitignore`。

## 主要修改内容

- 受限决策树模型：manifest 中每个 Profile 声明 `traits` 组合画像，`wizard.steps` 定义问题顺序与先决条件；选项永远从当前候选 Profile 推导，因此不会选出无法生成的组合，未接入的技术栈表现为"选项不出现"。候选在某 trait 上无差异的问题自动跳过（如非 dotnet 纯后端不问架构风格）。
- `--check` 追加 `WizardEngine.SimulateAll()`：全路径仿真保证每条回答路径收敛到恰好 1 个 Profile 且全部 Profile 可达，防止 manifest 调整引入歧义或漏配。
- 检测器输出可解释：推荐附带判断依据（如"发现 wails.json（Wails 桌面壳）"）与默认倾向说明。
- 交互层采用 Spectre.Console 0.52.0（不引入 Spectre.Console.Cli，现有参数面手写解析够用）：`ConsoleWizard` / `Program` 只依赖 `IConsoleUi`，交互终端走 `SelectionPrompt`（方向键 + 回车，问答「0 返回上一步」保留为选项项），stdin 重定向（echo 管道冒烟、CI）自动回落 `PlainConsoleUi` 纯文本编号输入；`--check` / `--emit` / `--detect` 输出不混入 ANSI 控制序列。
- 抽测审查发现两处生成器缺陷并修复：① `.ai-rule-profile.json` 在 Windows 下被写成 CRLF（`System.Text.Json` WriteIndented 缩进随系统换行符），违反仓库 LF 约定，已统一归一为 LF 并加单测断言；② `web-fullstack` 家族（.NET 后端 + Web 前端）的 .gitignore 默认模板误用纯 Node 模板，后端 `bin/obj/.vs` 未被忽略，已新增 webstack（Node + .NET 合并）模板并调整 `StackKeyFor` 映射，单测补映射与模板断言。
- 20 个预设 Profile 内容零变化；本次仅为 manifest 追加字段 + 版本号提升。
