### 修改原因（通用）
用户用 dotnetCoreSingle 模板临时项目（D:\Gitee\Temp\api）实测后反馈五类问题：
1. TASK.md 写了"已完成步骤""待用户确认"等过程叙述（应在写代码前以阶段门控确认，而非事后堆进文件）
2. AI 未单独确认就创建了 Docker 文件
3. 阻塞项被写入 TASK.md（在最终输出提醒即可，不必入文件）
4. 实现类补了实现细节型 `<remarks>`
5. 接口已注释的实现方法仍堆 `/// <inheritdoc />`

### 通用修改内容
- `AGENTS.md` 任务管理：单 Agent 单会话任务只记 7 个字段，不写"已完成步骤 / 待用户确认 / 阻塞项"；仅跨会话交接或明确阻塞才入文件
- `AGENTS.md` 纠错机制：阻塞项 / 交接说明改为按任务管理范围处理（仅交叉引用）
- `AGENTS.md` 最终输出要求：删除重复的"当前任务状态"条目（既有重复）
- `infra-AGENTS.md` Docker 总体要求：新增"首次创建 Dockerfile / Compose / .dockerignore 等部署文件前必须单独向用户确认"
- `backend-AGENTS.md` / `application-AGENTS.md` 代码注释规范：接口已注释时实现不重复 / 不加 `/// <inheritdoc />`；默认不写 `<remarks>`，仅 Controller action 对外契约可保留精简 remarks
- 顺带清理既有重复：技术债务评估框架改为指向根 `AGENTS.md`（各模板按出现位置：backend / infra / application）
- 各文件 frontmatter `version` / `last_updated` 同步更新
