## 修改原因

用户否决 T2（design-system.yaml 保持独立）后，要求继续审查其余部分。对全部跨 Profile 同名输出文件做标题级段配对（≥0.90，排除纯 include 段与 yaml），14 对候选逐对核验：10 对为 include 组合的预期全同（假阳性），真实残留为桌面双端 DTO 契约段（1 行漂移）与 tauri 常见任务入口（1 行漂移），执行收敛与修复。

【1.29.0 扩展原因】用户发起"用 exe 按一个技术栈实际生成 → 提出问题 → 确认后修复"流程。重新发布 exe 后为 reactTauriExe 生成 9 个文件并逐文件走查，发现共享段未按「桌面 vs 服务端」分家导致的系统性失配：`shared/infra/common-tasks.md` 按 web 服务器语境编写却被 10 个 Profile 引用，5 个桌面 Profile 的入口行大面积指向不存在的小节（数据访问规则、默认端口、Docker / 构建规则等），且包含桌面不适用的端口 / 连接串 / Docker 概念；`Models.cs` 的 checklist-infra 默认值使 18 个未覆盖 Profile 的根检查清单出现 Docker / 部署文档误导项；桌面前端共享段枚举 Electron IPC / .NET sidecar / Rust 后端造成跨栈噪音。用户确认后按 P1–P7 全量修复。

【1.44.0 扩展原因】用户发起"随机选一个技术栈生成并审查"流程，随机命中 dotnetBlazor，产物审查通过但发现工作区根 `AGENTS.md` 声明的通用执行约束「Windows / PowerShell 场景统一禁止 `&&` 链式命令」全仓库只剩 staticHtml frontend 本地一行（其余架构片段与 `shared/` 均无，且 `--check` 无法检测这类跨模板措辞缺口）。按「先统一口径、收敛唯一维护源」修复：禁令上收根模板，一处维护全部 Profile 生效，并以回归测试固化。

【1.45.0 扩展原因】1.44.0 修复后用户询问遗留待办，用 `--emit` 对全部 26 Profile 做口径覆盖面验证，发现中文注释口径在 10 个无 .NET 后端的 Profile 产物中整体缺失。根因：该口径只写在 `shared/backend/comment-rules.md` 与 `shared/application/comment-rules.md` 的结尾行，仅被 .NET 系后端 / 应用子规则 include，前端族共享片段 `code-organization.md` 无此行，python / flutter / tauri / next 等非 .NET 组合没有可依赖的挂载点；1.43.0 新增纯前端组合时继承了该缺口。两片段主体是 .NET 实质差异（Controller/Service 与 ViewModel 置换规则不同），按审计裁定不合并，仅统一结尾口径行措辞。
