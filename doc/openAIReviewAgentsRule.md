# 重新思考 GPT-6 Astra 的技能与提示词

> 完整的文档索引，请参阅 [llms.txt](/llms.txt)。通过在页面 URL 后追加 `.md`，即可获取文档页面的 Markdown 版本。

编码智能体已经取得了长足的进步，最佳实践也在快速变化。随着模型能力不断提升，过去需要大量引导和脚手架支撑的事情已不再必要。

如果你过去一年一直在项目中使用 Codex 等智能体，你可能已经积累了大量指令，以引导模型取得良好结果。每次版本发布都值得重新审视这些假设，而 GPT-6 Astra 更是让这一点比以往任何时候都重要。

这些指令可以有多种形式：技能、`AGENTS.md` 以及你的任务提示词，都在塑造模型完成工作的过程。

## 更好的技能

这些指令可以以技能形式呈现，本质上是存储为 Markdown 文件的提示词，也可以与资源和打包脚本一起分发。通常，它们最适用于指导特定工作流，或在使用某些应用时提供帮助。

如今，人们默认会在项目中打包大量技能，而每个技能都有名称和描述，这些内容会被加载到模型上下文中，让模型知道何时使用它们。但许多描述过于冗长，当加入太多技能时，Codex 会开始缩短它们的描述以适配上下文。最终模型看到的每条描述都变少，更难判断该选择哪个技能。

更糟的是，描述之间常常相互矛盾，或过度强调应使用技能的时机，导致模型加载了实际上无助于当前任务的指令。

创建技能的一个常见工作流是使用 `$skill-creator` 技能。我们最近更新了它的指导内容，以缓解实践中观察到的许多失败模式。

首先，技能描述应在尽可能短的同时，让模型清楚地知道何时使用它：

> 示例：技能描述。不佳：创建并验证 Postgres 架构迁移。在处理数据库、查询、模型或持久化时使用。良好：创建并验证 Postgres 架构迁移。在添加或修改迁移，或审查其部署时使用。

_这里，不佳的技能描述可能会促使模型在任何涉及数据库相关内容时都使用它，而不仅仅是当需要处理迁移时才使用。_

第二，有用技能的关键标志之一是渐进式披露。读取一个技能会占用上下文，使上下文逼近压缩，并引入可能不适用于当前任务的指导。对于包含多个工作流的技能，应将根文档设为一个极简路由，指向相关文档和脚本。给模型足够的指引，让它知道去哪里查找，而不强迫它读取当下无关的内容。

第三，许多技能被写成了详尽的流程指南或操作配方。模型在理解细微差别和模糊性方面已有很大提升，因此过去有帮助的过度具体指导，现在反而可能阻碍结果。

仓库中的技能还会指导其他贡献者的智能体，而它们可能使用不同的模型。对 Sol 或 Luna 有帮助的指导，可能会对 GPT-6 Astra 造成过度约束，因此请考虑哪些模型会用到你留下的指令。

## 保持 AGENTS.md 更新

由于 `AGENTS.md` 在模型在你的仓库中工作时始终适用，你应经常重新审视每条指令，并问自己它是否仍然必要。

要求每次编辑前都阅读一堆文档或完整的仓库地图，对于修复拼写错误这类修改而言是过度的。GPT-6 Astra 能够自行判断需要阅读什么，而不必在每次更改前都被要求审查整个项目。

> 示例：AGENTS.md 上下文。不佳：每次编辑前，读取 architecture.md、database.md 和 deployment.md。良好：使用 architecture.md 了解服务边界，使用 database.md 处理架构变更，并在准备部署时使用 deployment.md。

_在每次编辑前提示模型读取文件，是消耗上下文并拖慢工作进程的一种好方法。不过，只要指向的是与当前上下文相关的文档，指向某些文档仍然可能有帮助。请务必同步更新你的文档！_

早期模型需要鼓励才会运行测试并检查自己的工作。GPT-6 Astra 会自行这样做，因此相同的指令可能导致不必要的测试。

GPT-6 Astra 很周全，但在任务推进到什么程度时可能更谨慎。有时它需要一点推动才能继续。你可以使用 `AGENTS.md` 为某个你认为安全的特定工作流授予许可，例如本地测试套件：

> 本地测试使用可丢弃的测试夹具，并且没有生产环境访问权限。请运行它们，修复由所请求的更改导致的失败，并重新运行受影响的测试，每一步都无需请求批准。

## 决策边界

请仔细注意你描述边界的方式。如果早期模型曾在未获许可的情况下替你做了某些事情，你可能添加了强烈措辞，要求它先询问。那可能有用，但 GPT-6 Astra 作为我们最对齐的模型，判断力要好得多，只有在确信安全时才会执行任务——因此你应当如此对待它。

如果你之前设定边界是为了防止其他模型走得太远，而现在正切换到 GPT-6 Astra，请考虑更新相关措辞：Astra 可能把边界看得过于严重，并可能在本来可以继续的地方停下。

## 持续执行

如果你习惯了 GPT-5.6 Sol 接到请求后长时间持续工作，GPT-6 Astra 在何时停止方面可能会显得更谨慎。它可能完成一个初步实现后就回来请求你审查，而工作仍未做完。

在这种情况下，事先定义完成标准会很有帮助。你可能需要推动 Astra 继续工作，直到完全完成。如果任务包括让实现跑起来、检查结果并修复失败之处，请把这些纳入请求中。要求它在首次实现后停下来供你审查，会促使模型更早停止，因此请确认这是不是你真的需要做出的决定。

如果你希望它在首轮尝试之后继续探索，请说明你希望探索什么，以及它应在哪里停止。

新模型是一个彻底整理的好机会，但你无需手动审查所有事项：请 GPT-6 Astra 根据本文讨论的内容进行一次审计，然后去构建一些你过去不会尝试的东西！
