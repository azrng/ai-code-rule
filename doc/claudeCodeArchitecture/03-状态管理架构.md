# 03 - 状态管理架构

## 全局状态：`bootstrap/state.ts`

整个应用共享一个全局 `State` 单例，存储在 `src/bootstrap/state.ts` 中。

```typescript
type State = {
  // 路径
  originalCwd: string          // 启动时的工作目录
  projectRoot: string          // 稳定的项目根目录（worktree 不变）
  cwd: string                  // 当前工作目录

  // 费用追踪
  totalCostUSD: number
  totalAPIDuration: number
  totalToolDuration: number
  modelUsage: { [modelName: string]: ModelUsage }

  // 模型
  mainLoopModelOverride: ModelSetting | undefined
  initialMainLoopModel: ModelSetting
  modelStrings: ModelStrings | null

  // 会话
  sessionId: SessionId
  parentSessionId: SessionId | undefined
  isInteractive: boolean
  clientType: string
  sessionSource: string | undefined

  // 遥测
  meter: Meter | null
  sessionCounter: AttributedCounter | null
  costCounter: AttributedCounter | null
  tokenCounter: AttributedCounter | null

  // 日志
  loggerProvider: LoggerProvider | null
  eventLogger: ReturnType<typeof logs.getLogger> | null

  // Agent 颜色
  agentColorMap: Map<string, AgentColorName>
  agentColorIndex: number

  // 错误追踪
  inMemoryErrorLog: Array<{ error: string; timestamp: string }>

  // 插件
  inlinePlugins: Array<string>

  // 权限
  allowedSettingSources: SettingSource[]
  sessionIngressToken: string | null | undefined

  // Feature flags
  flagSettingsPath: string | undefined
  flagSettingsInline: Record<string, unknown> | null

  // ... 更多
}
```

**关键原则**：注释明确标注 `DO NOT ADD MORE STATE HERE - BE JUDICIOUS WITH GLOBAL STATE`，鼓励最小化全局状态。

## SessionState 状态机

独立于全局 State，会话有自己的状态机（`src/utils/sessionState.ts`）：

```typescript
type SessionState = 'idle' | 'running' | 'requires_action'

type RequiresActionDetails = {
  tool_name: string
  action_description: string   // 人类可读描述
  tool_use_id: string
  request_id: string
  input?: Record<string, unknown>
}
```

状态通知机制：
- `notifySessionStateChanged(state, details?)` — 广播状态变化
- `setSessionStateChangedListener(cb)` — 注册监听器
- 同时更新 `external_metadata`（供 SDK/外部消费者读取）
- 可选地通过 SDK 事件流广播（`CLAUDE_CODE_EMIT_SESSION_STATE_EVENTS`）

## AppState 模式

UI 层使用 React Context 管理应用状态（`src/state/AppState.ts`）：

```typescript
type AppState = {
  toolPermissionContext: ToolPermissionContext
  mcp: { clients, tools, commands, resources }
  // ... UI 相关状态
}
```

通过 `AppStateProvider` 注入，子组件通过 `useAppState()` 消费。

## React Context 层级

```
App
  └── FpsMetricsProvider
        └── StatsProvider
              └── AppStateProvider
                    └── ModalContext
                          └── OverlayContext
                                └── PromptOverlayContext
                                      └── NotificationsProvider
                                            └── QueuedMessageContext
                                                  └── 实际 UI 组件
```

每个 Context 职责单一：
- `FpsMetricsProvider` — 帧率监控
- `StatsProvider` — 使用统计（token、cost、时间）
- `AppStateProvider` — 核心应用状态
- `ModalContext` — 模态对话框管理
- `NotificationsProvider` — 通知队列
- `QueuedMessageContext` — 消息队列

## Signal 模式

项目使用自定义的 `createSignal()` 信号（`src/utils/signal.ts`），类似 SolidJS 的信号：

```typescript
const [get, set] = createSignal(initialValue);
// get() 读取当前值
// set(newValue) 更新值并通知订阅者
```

用于模块间的状态同步，避免 React 的 re-render 开销。

## 设计要点

1. **最小化全局 State**：明确注释不鼓励添加更多全局状态
2. **分层状态**：全局 State（运行时） → SessionState（会话生命周期） → AppState（UI 层）
3. **监听器模式**：状态变化通过回调广播，解耦生产者和消费者
4. **不可变性**：`ToolPermissionContext` 使用 `DeepImmutable<>` 包装
5. **文件锁**：`GlobalConfig` 使用 `lockfile` 保证多进程安全
