- [ ] 先确认本次只处理哪个架构目录，不要一轮同时改多个模板

- [ ] 先列出原文件中的一级章节和关键二级章节
- [ ] 确认该架构适合拆成哪些作用域目录，例如 `frontend`、`backend`、`doc`、`infra`
- [ ] 确认本次拆分后子文件数量是否控制在合理范围，避免过碎
- [ ] 确认根文件仍然要作为唯一入口文件，不改成“多个平级入口”

## 五、结构质量检查

- [ ] 根文件没有残留大段前后端细则
- [ ] 子文件没有承载无关作用域的内容
- [ ] 没有为了拆分而新造平行规则
- [ ] 没有出现同一规则在根文件和子文件重复堆叠
- [ ] 没有出现“标题还在根文件，但正文已经搬走”的断裂情况
- [ ] 没有出现“正文搬走了，但入口没有索引”的断裂情况

- [ ] 所有新文件都使用 UTF-8
- [ ] 中文内容显示正常，没有乱码
- [ ] 没有多余的 `---`
- [ ] 没有重复标题
- [ ] 没有重复说明段落
- [ ] 文件结尾格式统一

## 七、规则闭环检查

- [ ] 根文件已加入“重复错误回顾与规则更新机制”
- [ ] 机制中明确“同类错误连续两次”要触发回顾
- [ ] 机制中明确回顾结论要回写到 `AGENTS.md` 或子 `AGENTS.md`
- [ ] 若模板规则发生变更，已同步补 `devlog`

## 八、交付前检查

- [ ] 已确认本次只改目标架构，没有误改其他模板
- [ ] 已确认临时脚本、临时文件已清理
- [ ] 已新增对应变更记录文件
- [ ] 已让使用者按真实阅读路径测试一次
- [ ] 已记录本轮试点的经验与问题，供后续模板复用

## 推荐执行顺序

1. 先列章节，再定拆分目录。
2. 先改根入口，再迁移细则。
3. 先补索引和阅读顺序，再删原正文。
4. 先完成一个试点，再推广到相似模板。
