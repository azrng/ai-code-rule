## 处理原则

- A 组是冲突缺陷（技能与 rule 内容对立，导入即收到两套相反指令），优先级最高，不等批次直接修。
- B 组是安全 / 质量基线藏在可选技能里（未导入即不受约束），上移 rule 后技能内改引用。
- C 组是 rule 里的程序性手册（删除约束力不损失、只损失知识），按「拆基线 + 手册」处理：强制句留 rule，操作步骤移技能；无现成技能承接的新建技能（目录含 `SKILL.md` 放 `skills/` 对应分组，manifest `skills` 节点登记 `id` / `group` / `when`）。
- rule 侧为技能留的门控句必须自含成立：不依赖技能已导入也能按最小口径执行（技能只提供操作细节，强制要求始终在 rule）。
- 技能内容变更对照上游官方源核对，走 `doc/技能变更日志.md` 登记并升 `vars.version`；规则侧变更刷新 emit 基线。
- 每条处理完在本表标记处置结果，不凭单次判断成批删除。
