# 补充后端代码组织、注释规范与禁用主构造函数规则

- 本次目标：
  - 修复用户在 dotnetCoreSingle 模板实测中反复出现的四类问题：单文件塞多个类、核心方法无注释、请求 / 响应类堆一个文件、仍在使用 C# 主构造函数
- 问题根因：
  - 主构造函数：禁止主构造函数的规则此前只补到 `reactLinkdotNet` / `avaloniaExe` / `mauiMobile`，`dotnetCoreSingle` 当初被漏掉，故 AI 按 .NET 10 默认推荐使用
  - DTO 组织：backend-AGENTS.md 只说"DTO 按用途区分"，未规定"一个 DTO 一个文件"与目录组织，"避免堆叠"仅写在 doc-AGENTS.md，写代码时不命中
  - 注释：强制注释要求只在 Swagger 规范内，仅覆盖 Controller 公开方法，Service / Repository / 接口方法零约束
  - 单文件多类：缺少"一个文件一个主类型"约束，README 的"职责单一"过于宽泛
- 核心改动：
  - 在 `backend-AGENTS.md` Service 规则追加：禁止 Controller / Service / Repository / Entity / DTO 等 C# 类使用主构造函数，统一显式构造函数
  - 新增 `### 代码组织规范`：一个文件一个主类型、DTO 按业务域分子目录、Request / Response 分文件、拆分信号、允许例外、反模式
  - 新增 `### 代码注释规范`：Controller action 与 Service 核心方法必须 XML 注释、复杂业务分支优先行内注释、低价值注释不补
  - 精简 `### 数据模型规则` 的 DTO 条款，指向新代码组织规范，避免重复
  - Swagger 规范补一条，衔接代码注释规范
  - frontmatter 版本号 1.4.0 → 1.5.0，日期更新至 2026-07-07
