# AGENTS.md

## 适用范围

- 作用域：Next.js 页面、布局、组件、状态、样式与前端测试
- 触发场景：涉及 App Router、Server Component、Client Component、表单、交互、前端 smoke test 时阅读

### 阅读摘要
- 建议阅读：新增页面、改表单、改交互、改路由、改组件样式、补前端测试
- 可先跳过：纯服务端逻辑、Prisma、Docker、环境变量、仅文档说明改动
- 优先查看：`阶段 1`、`前端规则`、`测试规则`

### 常见任务入口
- 新增页面或布局：先看 `阶段 1`、`React / App Router 规范`
- 改表单、筛选、交互：先看 `React / App Router 规范`、`请求与数据获取规则`
- 改样式、组件展示：先看 `样式规则`、`组件规则`
- 补前端回归：先看 `提交前最小回归`、`前端测试`

## 技术栈

### 前端
- Next.js（App Router）+ React + TypeScript
- Tailwind CSS（唯一样式体系）
- `next/font`（统一字体接入）
- shadcn/ui + Radix UI（如仓库已使用则沿用）
- lucide-react（唯一图标库）
- React Hook Form + Zod（表单与校验）
- Zustand（仅用于：侧边栏折叠、全局筛选、通知、轻量会话上下文）

### 设计系统
- 所有视觉规范以 `design-system.yaml` 为唯一事实来源
- 优先复用项目已有组件、布局、样式变量与交互模式
- 禁止 inline style，禁止硬编码颜色、间距、圆角、阴影、断点

### 技术选择原则
如果仓库已经有真实实现，以现有代码为准，不要强行重构或替换技术栈。

**技术债务评估框架**：
- **沿用现有实现**：代码可正常运行、无明显性能问题、维护成本可接受、团队熟悉度高
- **必须重构**：存在安全漏洞、严重影响性能、阻碍新功能开发、维护成本过高
- **可选重构**：代码风格不一致、存在更好的替代方案、但不紧急
- **禁止重构**：仅为个人偏好、追赶技术潮流、非关键路径的过度优化

**重构决策流程**：
1. 先评估现有代码的技术债务等级（高/中/低）
2. 判断重构的紧急程度和业务价值
3. 评估重构风险和工作量
4. 高风险或大规模重构需先与团队确认

## 主动建议规则
- 发现页面结构、组件拆分、状态管理、样式体系、可访问性或交互一致性问题时，应主动提醒，并说明是否影响当前任务
- 发现已有页面、组件、hook、布局、token 或交互模式可复用时，应优先建议复用，不新增平行实现
- 发现设计稿、截图反馈或用户描述与现有设计系统冲突时，应先说明冲突点，再给出最小调整方案
- 涉及共享组件、布局或全局状态的建议改动，未经用户确认不得扩大到本次任务之外

## 阶段 1 — 页面与交互实现

**触发条件**：用户发出“开始前端开发”或等价指令

**入场要求**：阶段 0 设计文档已确认

**工作内容**：
1. 基于 Next.js App Router 实现页面、布局、组件和导航结构。
2. 优先使用 Server Component 搭建页面骨架，必要时再下沉到 Client Component。
3. 阶段内允许使用 mock 数据、假接口或静态数据文件，但页面交互必须完整可演示。
4. 同步产出契约说明：字段定义、筛选条件、分页参数、表单校验规则、权限要求。

**门控规则**：
- 用户确认页面符合设计文档预期。
- 页面交互逻辑经手工 smoke test 验证通过。

## 前端规则

### React / App Router 规范
- 页面、布局、模板统一使用 App Router 目录规范
- 默认使用 Server Component；只有需要交互时才使用 Client Component
- `use client` 只写在最小必要边界，不要整页下沉为客户端组件
- 表单优先使用 React Hook Form + Zod
- 页面状态优先使用 `loading.tsx`、`error.tsx`、`not-found.tsx`
- 复用逻辑使用 hooks，放在 `src/hooks/` 或按业务域收敛

### 组件通信规范
- 父传子：props
- 子传父：回调函数
- 跨组件共享的客户端状态：Zustand
- 仅 UI 级共享配置可使用 React Context
- 避免 props drill 过深；但不要为了少量传值滥用全局状态

### 路由管理规范
- 页面路由即文件系统路由，目录命名必须表达业务语义
- 页面跳转优先使用 `next/link`
- 客户端跳转使用 `useRouter`
- 服务端重定向优先使用 `redirect`
- 高级路由能力仅在明确有必要时使用

### 状态管理规范
- 服务端数据默认不存入 Zustand
- Server Component 优先直接读取服务层结果
- 客户端缓存若仓库已使用 TanStack Query，则沿用；否则根据技术债务评估框架决定是否引入新方案
- **缓存策略优先级**：TanStack Query 用于客户端数据缓存（浏览器端），Next.js 缓存用于服务端数据缓存（服务端），两者不得针对同一数据源重复缓存
- Zustand 仅用于侧边栏折叠、全局筛选、通知、轻量会话上下文等纯客户端状态

### 样式规则
- 统一使用 Tailwind CSS 与设计 token
- 字体统一通过 `next/font` 接入
- 优先复用项目现有 `ui` 组件、`cn()`、`cva` 或等价封装
- 禁止 inline style
- 禁止硬编码颜色值、阴影值、圆角值、z-index、断点
- 响应式遵循移动优先原则

### 组件规则
- 优先复用 `src/components/` 与 `src/features/` 现有组件
- 只有确认存在复用价值时，才新增共享组件
- 页面状态必须完整：`loading`、`empty`、`error`、`no-permission`
- 不要为单次需求过度抽象组件

### 请求与数据获取规则
- Server Component 内禁止为了取同站点数据再请求自己的 `/api`
- 页面读操作优先直接调用服务层函数
- 浏览器端访问同站点接口统一使用相对地址 `/api`
- 业务写操作优先 Server Action，成功后使用 `revalidatePath` / `revalidateTag`
- 客户端不得直接持有数据库连接、服务端密钥或服务端专用环境变量

## 测试规则

### 总体要求
- 影响行为的改动应优先补充或更新测试
- 若本次改动未补测试，必须在最终说明中写明原因和风险
- 测试应覆盖真实业务路径，而不是只验证静态渲染

### 提交前最小回归
- 默认执行：`lint`、`typecheck`
- 页面、路由、表单、交互改动：至少补一次受影响页面或组件的手工 smoke test，或等价的自动化验证
- **微小调整**（文案修改、颜色调整、间距优化等不影响逻辑的改动，修改内容少于10行）：可不补自动化测试，但仍应检查受影响页面显示、状态和关键交互未回退
- 若改动影响共享组件、布局或状态流转，优先补受影响范围最大的页面验证，而不是只看局部组件

### 前端测试
- 组件测试优先使用 Vitest + Testing Library
- 关键页面至少应完成一次手工或 Playwright smoke test
- Client Component 的交互、校验、禁用态、错误态应有验证

### 无法执行测试时
- 必须说明未执行的测试类型
- 必须说明未执行原因
- 必须说明潜在影响范围与风险
