# 同步后端代码组织、注释与禁主构造函数规则

- 本次目标：
  - 将 dotnetCoreSingle / dotnetLayered 已补齐的四项规则适配 Clean Architecture（Web/Application/Domain/Infrastructure）同步到 dotnetBlazor
- 问题根因：
  - 禁主构造函数：本模板此前缺失，AI 按 .NET 10 默认推荐使用主构造函数
  - 代码组织：只有分层骨架树，未规定"一个文件一个主类型"和 DTO 拆分
  - 注释：无任何注释强制要求，Controller / Service / Domain 核心方法零约束
  - 目录职责：只有层骨架树，未说明层内各类放哪个目录、如何命名
- 核心改动：
  - backend-AGENTS.md Service 层规则追加：禁止 Controller / Service / Domain 实体 / DTO 等 C# 类使用主构造函数
  - 新增「层内目录组织」表：Web / Application / Domain / Infrastructure 各层内部的类型、目录与命名约定
  - 新增「代码组织规范」：一个文件一个主类型、DTO 按业务域组织、拆分信号、允许例外、反模式
  - 新增「代码注释规范」：Controller action、Application 服务接口/核心方法、Domain 核心规则必须 XML 注释
