## 最小充分上下文
- 简单问题（纯问答、单文件、不影响业务逻辑、不新增依赖）与单点低风险改动（单文件、不影响核心链路、不涉及权限 / 缓存 / 迁移 / 发布）：只读命中的子规则和目标文件，不默认预读全部子规则
- 只有在需要实际落文件、任务跨{{context-scope-nouns}}、涉及{{high-risk-nouns}}等高风险内容、或当前信息不足以判断影响范围时，才继续补读更多规则或实现文件
- 任务升级时按命中场景逐步补充上下文，而不是一开始加载全部信息

## 根文件原则
- 根 `AGENTS.md` 只放所有任务都需要知道的规则，不重复展开{{root-scope-nouns}}细节
- 用户指令始终高于本文件
- 不盲从用户前提：发现更优思路、遗漏或矛盾时先说明理由与影响，再按用户最终决定执行；细则见 `collaboration-AGENTS.md`「坦率反馈与过程沟通」
- 先理解业务目标与现有实现，再修改代码或规则；优先复用既有结构，避免无关重构和过度设计
- 代码先服务于人，再服务于机器：方案先按 KISS 收敛，核心逻辑优先直白写法，复杂分支用行内注释说明“为什么”
- 优先做可验证的改动；无法验证时必须说明原因、影响和建议下一步

## 全局工作规则
- 实际修改前，确认任务类型、命中子规则、目标实现、复用点、影响范围、验证路径和待确认项；不相关项跳过
- 不确定 API、依赖版本、文件、业务规则、{{verify-nouns}}配置或命令结果时，依次查项目实现与测试、相关文档和任务记录、锁定版本或官方文档；仍无法确认时询问用户，禁止把假设写成事实
{{verify-quote}}
- 新增功能或较大改动前，先检索相似实现（{{search-nouns}}）；保持最小扰动，不做无关格式化、重构、依赖升级或方案替换
- 修 Bug 必须定位根因并验证原始复现场景；涉及{{boundary-nouns}}、数据流、权限、缓存、状态流转或持久化时，先判断架构边界
- 发现复用点、需求缺口、职责边界、验证缺口或风险时，按“必须处理 / 建议处理 / 暂不处理”说明；未经用户确认不得扩大范围
{{model-behavior-extra}}
- 删除文件、删除目录、批量重构、{{destructive-nouns}}等高风险操作，必须先获得明确确认

## 编码硬约束
- 所有源码、配置、文档统一使用 `UTF-8`；中文显示异常时，未确认是显示问题还是文件损坏前禁止覆盖
- 编写注释时统一使用中文，不使用纯英文注释
- PowerShell 命令不接受 `&&`，禁止使用；需要连续执行时改为分步执行或使用 PowerShell 兼容写法。
- Git 暂存一律按文件显式点名：`git add -- <文件1> <文件2>`；禁止 `git add .`、`git add <目录>`、`git add -A`、`git add -u`、通配符等批量暂存及 `git commit -a`。提交前逐文件、逐差异核对本任务范围，细则见 `collaboration-AGENTS.md`「Git、验证与交付」。

## 触发式协作规则
- 新功能、行为变更或用户使用 `/plan`：在形成计划前读取 `collaboration-AGENTS.md` 的「需求澄清与计划关卡」；纯问答、明确的低风险单点修改或用户要求直接执行时按其中的跳过条件处理
- 发现前提矛盾或更优思路、需要自行判断常规细节，或需要同步过程进展时：读取 `collaboration-AGENTS.md` 的「坦率反馈与过程沟通」
- 实际修改、`TASK.md` 维护、验证、交付、提交、回退、重复问题回顾或规则效果反馈：读取 `collaboration-AGENTS.md` 的对应章节
- 检测到其他 AI 会话并行操作同一工作区（`TASK.md` 出现非本会话条目、文件被会话外修改或输出目录被运行实例锁定）时：读取 `collaboration-AGENTS.md` 的「并行会话隔离」
- 提交、推送与暂缓：读取 `collaboration-AGENTS.md`「Git、验证与交付」——验证通过后默认提交本任务改动（不自动推送）；用户明确要求暂缓或禁止提交时不提交。“开始开发”“完成实现”“交付收口”等指令不等同于推送授权
