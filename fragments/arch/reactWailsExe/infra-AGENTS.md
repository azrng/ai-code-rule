# 基础设施规则

## 适用范围

- 作用域：环境变量、启动方式、构建发布、部署链路与交付验证规则
- 触发场景：涉及启动命令、环境变量、构建打包、部署脚本、容器化、CI/CD 时阅读

### 常见任务入口
- 改容器或构建配置：先看 `运行与部署原则`
- 改端口、环境变量、连接串：先看 `环境变量规则`
- 改启动命令、发布或打包链路：先看 `部署与发布交付规则`
- 补交付回归：先看 `提交前最小回归`

## 运行与部署原则

### 总体要求
- 优先复用现有 `wails.json` 构建配置
- 仅支持 Windows 平台发布
- 使用 `wails build -platform windows/amd64` 构建可执行文件
- 不要把密钥写入配置文件
- 部署链路必须可追踪、可复现
- 清理旧版本时要保留最小回滚窗口

### 部署与发布交付规则
- 只要本次任务新增或修改了运行端口、环境变量、构建脚本、启动命令、Dockerfile、Compose、安装包脚本或发布链路，完成实现后应主动执行一次构建与启动验证；若环境限制无法执行，必须明确说明
- 部署验证至少包括：
  - 构建、打包或镜像生成是否成功
  - 主要服务或应用是否成功启动
  - 关键功能是否处于可用状态
  - 核心访问链路是否可用
- 若发现端口冲突，不要直接停止未知本地进程；优先调整当前项目配置，并同步更新文档和配置

### 环境变量规则
- 外部服务地址、数据库连接串、鉴权密钥等必须通过环境变量或项目约定的安全配置方式管理
- 新增环境变量时必须同步更新 `.env.example` 或对应配置示例
- 禁止把密钥、连接串或敏感信息硬编码在源码、配置文件或安装包模板中
