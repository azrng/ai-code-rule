# 前端规则

## 适用范围

- 作用域：界面、页面、视图、组件、交互、样式与前端测试
- 触发场景：涉及任何用户可见界面、前端交互、客户端状态、组件拆分、界面回归时阅读

## 技术栈

### 通用原则
- 不预设具体前端框架、语言、组件库、样式方案或状态管理工具
- 路由、状态管理、表单校验、构建工具、请求封装均以现有项目为准，不因个人偏好强行替换
- 如项目已有统一 UI 组件库、样式体系、图标库、请求封装或页面基座，必须优先复用

### 设计系统
- 所有视觉规范以 `design-system.yaml` 为唯一事实来源
- 优先复用项目已有组件、布局、样式变量与交互模式
- 禁止在无约束情况下随意硬编码颜色、间距、圆角、阴影、断点；若现有技术栈无法完全避免，必须优先抽成可复用 token 或常量

## 阶段 1 — 页面与交互实现

**触发条件**：用户发出“开始前端开发”或等价指令

**入场要求**：阶段 0 设计文档已确认

**工作内容**：
1. 基于当前项目使用的界面技术实现页面、布局、组件和导航结构。
2. 先搭建页面骨架、数据状态和交互闭环，再补细节优化。
3. 阶段内允许使用 mock 数据、假接口或静态数据文件，但页面交互必须完整可演示。
4. 同步产出契约说明：字段定义、筛选条件、分页参数、表单校验规则、权限要求。

**门控规则**：
- 用户确认页面符合设计文档预期。
- 页面交互逻辑经手工 smoke test 验证通过。
- 显示层契约、字段说明和 schema / 类型定义已初步定稳；后续发现缺口时按根 `AGENTS.md` 的纠错与回退机制处理。

## 前端规则

### 页面与组件规范
- 页面、布局、视图、组件应遵循当前项目的目录结构与分层习惯
- 页面容器负责组织数据和状态，纯展示逻辑尽量下沉到组件
- 单个页面、组件、hook、store 保持职责单一，发现持续膨胀时及时拆分
- 交互组件仅在最小必要边界承载客户端逻辑，不要把整页都做成重状态容器或巨型页面类

### 组件通信规范
- 父传子：props 或等价输入参数
- 子传父：回调函数或等价事件机制
- 跨组件共享的客户端状态：仅在确有复用价值时使用统一状态方案
- 仅 UI 级共享配置可使用上下文容器或依赖注入方式
- 避免 props drill 过深；但不要为了少量传值滥用全局状态

### 路由管理规范
- 路由组织必须表达业务语义，不使用难以理解的临时命名
- 页面导航优先使用当前项目既有的路由能力或导航机制
- 重定向、鉴权跳转、404 处理、嵌套路由等高级能力，仅在明确有必要时使用

### 状态与数据流规则
- 服务端主数据源不要长期塞进纯客户端全局状态中
- 优先沿用项目已有的数据请求、缓存和失效策略
- 同一份数据只保留一个主要事实来源，避免页面本地状态、全局状态、缓存层互相打架
- 写操作成功后必须刷新受影响视图，禁止出现“提交成功但页面没更新”的伪完成状态

### 样式规则
- 统一使用项目现有样式体系与设计 token
- 优先复用项目现有 `ui` 组件、样式变量、主题配置、原子类封装或等价能力
- 尽量避免 inline style；若现有技术栈或组件机制必须使用，需保持样式来源可复用、可追踪
- 禁止随意硬编码颜色值、阴影值、圆角值、z-index、断点
- 响应式遵循移动优先原则

### 组件规则
- 优先复用现有组件目录与业务域模块
- 只有确认存在复用价值时，才新增共享组件
- 页面状态必须完整：`loading`、`empty`、`error`、`not-found`、`no-permission`
- 不要为单次需求过度抽象组件

### 表单规则
- 表单校验优先复用项目已有 schema、校验器或共享类型定义
- 错误反馈必须可读、可恢复，不允许只通过颜色表达错误
- 提交中需有明确禁用态或 loading 态，避免重复提交
- 失败后默认保留用户输入，除非业务上必须清空

### 请求与前端数据获取规则
- 客户端请求应通过项目统一封装、统一网关地址或现有调用方式发起，不要在页面里散落硬编码环境地址
- 前端只负责消费服务端提供的数据和权限结果，不在客户端补造安全边界
- 若当前技术栈支持服务端渲染、预取或本地缓存，优先沿用现有方案，不做无意义绕路请求

## 测试规则

<!-- include: shared/frontend/general-requirements.md -->

### 提交前最小回归
- 默认执行：项目已有的静态检查，如 `lint`、`typecheck`、组件检查或等价命令
- 页面、路由、表单、交互改动：至少补一次受影响页面或组件的手工 smoke test，或等价的自动化验证
- **微小调整**（文案修改、颜色调整、间距优化等不影响逻辑的改动，修改内容少于10行）：可不补自动化测试，但仍应检查受影响页面显示、状态和关键交互未回退
- 若改动影响共享组件、布局或状态流转，优先补受影响范围最大的页面验证，而不是只看局部组件

### 前端测试
- 组件测试优先使用项目当前采用的测试方案
- 关键页面至少应完成一次手工或自动化 smoke test
- 交互、校验、禁用态、错误态应有验证
