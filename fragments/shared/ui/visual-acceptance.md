### 视觉验收

- 触发时机：视图实现完成、进入业务开发之前，对每个已实现页面执行视觉验收；无 UI 改动的任务跳过

#### 逐页截图对比
- 对每个已实现页面分别截图，与确认后的原型并排对比；原型为 HTML 时直接打开原型页面截图，同栈原型运行后截图
- 截图应覆盖关键状态：默认态，以及必要的加载中、空数据、错误、无权限等状态反馈
- 截图与对比结论统一放 `artifacts/visual-acceptance/<任务名>/`，多会话并行时各自独立目录，不覆盖其他会话产物

#### AI 自检清单
逐页按以下维度自检，维度与 `design-system.yaml` 的 token 分类对应：

- 布局结构：页面骨架、导航、区域划分与原型一致，无缺失或多余区块
- 间距：内边距、外边距、栅格 / 断点取值符合锁定的 spacing token
- 颜色：主色、语义色（成功 / 警告 / 错误 / 信息）、文本与背景色符合锁定的 colors token，无硬编码色值
- 字体：字体族、字号、字重、行高符合锁定的 typography token
- 关键状态完整性：loading、empty、error、no-permission 等状态均已实现且表现与原型一致

#### 差异报告
- 发现差异时逐条记录：页面、维度、原型取值、实现取值、差异原因（实现偏差 / 原型不合理 / token 未覆盖）
- 实现偏差按锁定规范修正；属规范本身需调整的，先走 UI 规范锁定的变更确认流程，不得顺手改 token
- 自检通过后输出简明结论清单（每页一行：通过 / 已修正 / 待用户裁决）

#### 用户终审门控
- 自检与修正完成后，把并排对比与结论清单提交用户终审
- 用户终审通过才算视觉验收通过，方可进入业务开发；未通过项回到视图实现修正后重新验收
