### 视觉验收

- 触发时机：视图实现完成、进入业务开发之前，对每个已实现页面执行视觉验收；无 UI 改动的任务跳过
- 命中「原型设计与确认」跳过条件的微小界面改动（字段增删、文案 / 样式微调）：免逐页截图对比与用户终审，只执行间距 / 颜色 / 字体三维的代码审查，确认后随任务交付；本条只放宽视觉验收力度，已有对应原型的项目仍按「原型设计与确认」同步更新原型并经用户确认

#### 验证手段分层
- 截图验证结构与状态：布局结构、关键状态完整性两维以「逐页截图 + 与原型并排对比」为准
- 代码验证 token 取值：间距、颜色、字体三维以代码审查为准——检索界面代码中的硬编码色值 / 间距 / 字号，核对取值是否来自锁定后的 `design-system.yaml` token 及其实现资源（样式资源 / 主题配置）；截图只作辅助目测，不作为这三维的判定依据
- 自动化快照对比（可选增强）：Web 或浏览器可自动化的混合壳（Electron / Tauri / Wails）项目，经用户确认引入 Playwright 等工具后，可用视觉快照测试（如 `toHaveScreenshot()`）自动执行「逐页截图 + 并排对比」：以确认后的原型页面为基准快照，实现页面在相同浏览器、相同视口、对齐的模拟数据下截图比对；快照结果只用于布局结构与关键状态完整性两维的判定，不改变间距 / 颜色 / 字体以代码审查为准的口径
- 基准快照更新守卫：基准快照 / 基准截图只能在用户确认差异合理后才可更新，禁止为实现结果顺手刷新基准、把实现偏差固化为新基准
- 桌面 / 移动端无浏览器自动化能力时，以「可运行演示 + 平台自带截图（窗口截图 / 真机截图）+ 用户实机查看」为主，不强制逐页自动截图；代码审查两维照常执行

#### 逐页截图对比
- 对每个已实现页面分别截图，与确认后的原型并排对比；原型为 HTML 时直接打开原型页面截图，同栈原型运行后截图
- 对比双方截图条件保持一致：原型与实现使用对齐的模拟数据（列表条数、文案长度一致），并在相同浏览器与相同视口下截图，避免数据内容差异被误判为布局差异
- 截图应覆盖关键状态：默认态，以及必要的加载中、空数据、错误、无权限等状态反馈
- 响应式界面至少在桌面与窄屏两个目标视口分别截图；导航切换、侧栏抽屉等状态控件需在两个视口分别触发并确认可见状态变化，不得只验证单一视口

#### AI 自检清单
逐页按以下维度自检，维度与 `design-system.yaml` 的 token 分类对应；每维标注判定手段（截图对比 / 代码审查）：

- 布局结构（截图对比）：页面骨架、导航、区域划分与原型一致，无缺失或多余区块；存在固定顶栏 / 固定侧栏 / 安全区等固定 UI 区域时，首屏首行内容不得进入固定区域（自定义容器 padding 覆盖组件库 / 框架为固定栏预留的留白是高发原因）
- 间距（代码审查）：内边距、外边距、栅格 / 断点取值来自锁定的 spacing token，无硬编码数值
- 颜色（代码审查）：主色、语义色（成功 / 警告 / 错误 / 信息）、文本与背景色来自锁定的 colors token，无硬编码色值
- 字体（代码审查）：字体族、字号、字重、行高来自锁定的 typography token，无硬编码字号行高
- 关键状态完整性（截图对比）：loading、empty、error、no-permission 等状态均已实现且表现与原型一致

#### 差异报告
- 发现差异时逐条记录：页面、维度、原型取值、实现取值、差异原因（实现偏差 / 原型不合理 / token 未覆盖）
- 实现偏差按锁定规范修正；属规范本身需调整的，先走 UI 规范锁定的变更确认流程，不得顺手改 token
- 实现偏差的修正优先级：优先通过主题配置与组件参数还原原型，其次经主题 / 样式资源以 token 引用做局部调整，仍无法合理还原时在结论清单标注差异与原因待用户裁决；不得为迁就组件库默认样式反向修改原型
- 自检通过后输出简明结论清单（每页一行：通过 / 已修正 / 待用户裁决）

#### 用户终审门控
- 自检与修正完成后，把并排对比与结论清单提交用户终审
- 用户终审通过才算视觉验收通过，方可进入业务开发；未通过项回到视图实现修正后重新验收
