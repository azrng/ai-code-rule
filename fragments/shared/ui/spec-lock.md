### UI 规范锁定

- 原型经用户确认后，必须把原型中敲定的视觉规范回填 `design-system.yaml`：按「基线待定制 → 已定制」的状态机执行，把确认后的颜色、字体、间距、圆角、阴影等取值写入对应 token，并把 `meta.status` 置为「已定制」
- `meta.status` 为「已定制」即视为 UI 规范已锁定：此后的界面任务直接以锁定后的 token 为准，不再重新询问视觉偏好
- 调整顺序沿用设计系统基线规则的固定顺序：先改 `design-system.yaml`，再同步文件中声明的实现资源（样式资源 / 主题配置 / 图表主题），最后改界面
- 锁定后任何视觉 token 变更（改值、增删 token、调整主题策略）必须先向用户说明变更内容与影响范围，经用户确认后才可修改；未经确认不得擅改
- 解锁流程：用户主动提出调整，或 AI 发现规范与产品需求 / 可用性冲突必须调整时，先给出变更提案（改什么、为什么、影响哪些页面），用户确认后按固定顺序修改并保持 `meta.status` 为「已定制」；仅当整体推翻重来（如品牌重塑、技术栈更换）时才改回「基线待定制」重新走定制流程
- token 的命名、分层与「token → 实现资源 → 组件」引用管线仍属结构契约：可改值、增删 token，不得另建平行 token 体系或在界面绕过 token 硬编码
