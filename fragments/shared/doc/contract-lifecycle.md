## 契约生命周期

- 已存在的接口、DTO、Schema 或事件契约：若尚无 `CON-` 编号，先在 `doc/contracts/<module>.md` 增加只含编号、来源路径、状态和用途的索引项；设计文档只引用 `CON-` 编号、最终事实来源路径和本次使用范围，不复制完整字段结构。
- 新增契约时，阶段 0 先创建 `doc/contracts/<module>/<feature>.md` 作为契约草案，标注稳定的 `CON-` 编号和 `status: draft`；完整请求、响应或事件字段只维护在该草案中，不写入需求或设计正文。
- 阶段 0 的设计文档必须引用对应的 `CON-` 编号，并明确契约是已有事实来源还是待落地草案；不能把尚不存在的 DTO、Schema 或 Swagger 文档写成已确认事实。
- 用户确认需求、设计和新增契约草案后，才允许进入阶段 1。阶段 1 将草案落地为项目 DTO、Schema、接口或事件定义后，代码 / Schema 成为最终事实来源；契约草案只保留来源链接和变更记录，并标记为 `superseded`，不得继续维护第二份完整字段表。
- 阶段 1 或后续实现发现契约缺口时，先回到契约变更流程；不得在实现层临时补字段或让前端、调用方私自约定未记录的结构。
