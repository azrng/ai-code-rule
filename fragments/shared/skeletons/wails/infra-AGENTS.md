# 基础设施规则

## 适用范围

- 作用域：环境变量、启动方式、构建发布、部署链路与交付验证规则
- 触发场景：涉及启动命令、环境变量、构建打包、部署脚本、CI/CD 时阅读

### 常见任务入口
- 改构建或打包配置：先看 `运行与部署原则`
- 改环境变量、外部服务地址或连接串：先看 `环境变量规则`
- 改启动命令、发布或打包链路：先看 `部署与发布交付规则`
- 补交付回归：先看 `提交前最小回归`

## 主动建议规则
- 发现环境变量、启动方式、构建脚本、打包配置、CI/CD 或发布链路存在不一致、不可复现或文档缺失时，应主动提醒
- 发现可以复用现有启动脚本、打包脚本、环境变量命名或发布脚本时，应优先建议复用，不新增平行部署链路
- 不确定外部服务地址、密钥来源、安装路径或运行命令时，应按根 `AGENTS.md` 的查证优先级处理，禁止凭经验写死配置
- 涉及清理环境、删除数据、停止未知进程、修改部署配置等高风险操作时，只能提出建议，必须等待明确确认后执行

## 运行与部署原则

### 总体要求
- 优先复用现有 `wails.json` 构建配置
- 仅支持 Windows 平台发布
- 使用 `wails build -platform windows/amd64` 构建可执行文件
- 不要把密钥写入配置文件
- 部署链路必须可追踪、可复现
- 清理旧版本时要保留最小回滚窗口

### 部署与发布交付规则
- 只要本次任务新增或修改了环境变量、构建脚本、启动命令、打包配置、安装包脚本或发布链路，完成实现后应主动执行一次构建与启动验证；若环境限制无法执行，必须明确说明
- 部署验证至少包括：
  - 构建、打包是否成功
  - 应用是否成功启动
  - 关键功能是否处于可用状态
  - 核心操作链路是否可用
- 若发现本地进程占用导致无法启动，不要直接停止未知进程；优先调整当前项目配置，并同步更新文档

### 环境变量规则
- 外部服务地址、数据库连接串、鉴权密钥等必须通过环境变量或项目约定的安全配置方式管理
- 新增环境变量时必须同步更新 `.env.example` 或对应配置示例
- 禁止把密钥、连接串或敏感信息硬编码在源码、配置文件或安装包模板中

## 阶段 3 — 联调与交付

**触发条件**：用户发出「开始联调」「开始交付」或等价指令；未明确发出时，阶段 2 门控全部满足后按 `collaboration-AGENTS.md`「Git、验证与交付」继续收口

**入场要求**：阶段 2 门控已全部满足；前端 mock 已替换为真实 Wails 绑定调用，发现的契约缺口均已按 `collaboration-AGENTS.md`「纠错、回退与重构」处理完毕

**工作内容**：
1. 前端从 mock 数据切换到 Wails 绑定调用，逐页面联调核心链路。
2. 按改动类型执行本文件与 `frontend-AGENTS.md`、`backend-AGENTS.md` 的「提交前最小回归」对应项。
3. 通过 `wails dev` 完成运行验证，通过 `wails build -platform windows/amd64` 完成构建验证，确认应用可启动、关键功能可用。
4. 按 `collaboration-AGENTS.md`「Git、验证与交付」汇总交付说明：已执行与未执行的校验、风险与待确认项。

**门控规则**：
- 前后端联调的核心链路验证通过；未执行的验证项已说明原因、影响范围和建议下一步。
- 文档、`TASK.md` 与示例配置已同步。
- 用户未明确要求提交时不得执行 `git commit`；提交时信息符合根 `AGENTS.md`「Commit 规范」。
