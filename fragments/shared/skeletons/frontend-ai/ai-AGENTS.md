# AI 规则（前端）

> 本规则规定浏览器侧的模型调用封装、密钥安全、流式处理、Prompt、会话管理与可选扩展能力；选型理念为「核心做扎实，可选按需引入，先闭环再扩张」。

## 适用范围

- 作用域：模型调用封装、密钥与代理、流式输出、Prompt、会话状态、AI 交互展示与 AI 相关测试
- 触发场景：涉及任何模型对接、流式交互、Prompt 编写、会话管理或 AI 界面实现时阅读

### 常见任务入口
- 接入或切换模型 / 网关：先看模型调用与密钥安全规范
- 做打字机 / 流式输出：先看流式处理规范
- 调输出格式或行为：先看 Prompt 规范
- 做对话或多会话界面：先看会话与状态管理规范
- 处理限流、超时、内容审核报错：先看错误处理与降级规范

---

## 核心 vs 可选（务必先读）

| 能力 | 分层 | 第一版是否需要 | 说明 |
| --- | --- | --- | --- |
| 统一模型调用封装（`src/ai/` 或等价） | 核心 | ✅ 需要 | 所有模型交互的唯一入口，组件不得绕过 |
| 托管网关 / 服务端代理 | 核心 | ✅ 需要 | 密钥不下发浏览器的硬前提 |
| 流式输出（SSE / ReadableStream） | 核心 | ✅ 视需要 | 对话或长文本生成建议启用 |
| 会话与消息状态管理 | 核心 | ✅ 视需要 | 多轮对话 / 多会话时引入 |
| 结构化输出（JSON 输出 + 校验） | 可选 | ❌ 暂不 | 需要模型驱动界面动作或稳定字段时引入 |
| 本地向量 / RAG | 可选 | ❌ 暂不 | 出现"对本地文档问答"需求时再评估 |
| 多模态（图片 / 语音） | 可选 | ❌ 暂不 | 按 Provider 能力与产品需要引入 |
| 多模型路由 / 降级链 | 可选 | ❌ 暂不 | 确有成本或可用性诉求时引入 |

> 判断准则：第一版只为跑通"用户输入 → 模型 → 流式展示 → 用户确认 → 下一步"。除此之外的能力一律先记为待确认，不默认引入。

## 技术栈

### 接入方式（三选一，以项目现状为准，不并存多套）
1. **托管网关**（Cloudflare AI Gateway / Vercel AI Gateway / OpenRouter 等）：浏览器持网关地址，密钥与配额策略在网关侧管理，按网关官方文档配置
2. **服务端代理 / BFF**（部署平台的 Functions / API Routes / 轻量代理）：浏览器只请求自家代理地址；这是无独立后端项目后续补 BFF 的推荐演进路径
3. **浏览器直连**：仅当 Provider 明确支持公开密钥 + 域名白名单（或本地 / 免费端点）时可用，必须经用户确认并在设计文档记录风险

### SDK 与配置
- 优先使用 Provider 官方 JS SDK 或 OpenAI 兼容客户端，且只在封装层内使用；封装层对外导出与 UI 无关的纯接口
- 网关地址、模型名、超时、功能开关通过 `VITE_` / 构建配置注入；密钥一律不进前端变量（见密钥安全规范）
- 切换 Provider / 网关只改封装层配置，不改组件与页面

## 主动建议规则
- 发现组件绕过封装层直接 fetch 模型接口或散落拼请求时，必须提醒并收敛到封装层
- 发现任何密钥被打进源码、前端环境变量或构建产物时，必须提醒迁移到托管网关 / 服务端代理
- 发现 Prompt 散落在组件字符串里、难以维护或测试时，建议沉淀到 `src/ai/prompts/`
- 发现流式输出缺少中断、错误、空响应处理时，应主动提醒
- 发现可以复用既有封装、Hook / 组合式函数或消息组件时，应优先建议复用
- 不确定 Provider 能力、SDK 版本行为时，应按根 `AGENTS.md` 的查证优先级处理，禁止按通用经验补写规则

## 模型调用与密钥安全规范

### 密钥红线
- 浏览器产物中不得出现任何模型服务的主密钥：不写入源码、不写入 `VITE_` / `NEXT_PUBLIC_` 前缀变量、不进打包产物与 source map
- 模型调用必须经托管网关或服务端代理；浏览器直连仅限 Provider 明确支持的公开端点且经用户确认
- 网关 / 代理地址、模型名通过环境变量注入并同步 `.env.example`（细则见 `infra-AGENTS.md`）
- 域名白名单、CORS、Referer 限制按 Provider / 网关官方文档配置并记录到文档

### 封装层规范
- 所有模型交互统一走 `src/ai/`（或项目等价目录）封装，组件只消费封装层导出的接口
- 封装层导出框架无关的接口（如 `streamChat(messages, options)` 返回异步可枚举增量），UI 订阅用自定义 Hook / 组合式函数包装
- 测试中用 mock 客户端替换封装层依赖，不真实调用模型服务
- 会话数据（如需持久化）走 `frontend-AGENTS.md` 无后端数据口径的本地存储封装，键名统一前缀

### 目录结构建议
```text
src/
└── ai/
    ├── clients/                # 模型客户端与网关配置构建
    ├── prompts/                # Prompt 模板与片段（集中管理）
    ├── types.ts                # 消息、流式事件、结构等类型定义
    └── hooks/ 或 composables/  # useChat / useAiStream 等订阅与状态
```

## 流式处理规范
- 统一使用封装层的流式接口处理 SSE / ReadableStream，不在组件里手写 EventSource / fetch 流解析
- 必须处理：用户主动中断（AbortController）、网络中断、超时、空响应、错误事件
- 渲染节流：增量内容合并渲染，避免每个分片触发全列表重渲；长回复按块追加
- 生成中禁止重复提交；中断后的续传或重试策略必须明确
- 流式事件契约（事件类型、字段、状态流转）变更时，按 `doc-AGENTS.md` 的口径变更流程同步文档

---

## Prompt 规范
- Prompt 模板集中放 `src/ai/prompts/`，不散落在组件
- 系统提示、角色设定、输出格式约束与用户变量分开组织，便于审查与测试
- 输出格式尽量结构化（JSON / 固定字段），解析前必须校验；解析失败给可读错误与重试入口
- Prompt 核心逻辑变更视为高风险改动（影响输出行为），需在最终说明中写清原因与验证方式
- 不在 Prompt 中放置用户隐私数据；模型输出不盲信，渲染前必须安全处理

---

## 会话与状态管理规范
- 消息结构统一（role / content / 状态 / 时间戳 / 可选错误信息），多会话按 id 组织
- 上下文窗口裁剪：发送前按上限截断或摘要，策略集中实现，不散落在调用点
- 会话持久化（如需）只存必要字段；清空会话属于本地数据破坏性操作，按根 `AGENTS.md` 高风险确认
- 重试、编辑后重发、删除消息等写操作成功后必须刷新受影响视图，不留伪完成状态

---

## 错误处理与降级规范
- 限流（429）、超时、鉴权失败、内容审核拦截必须转为用户可读的提示，不暴露原始报错与内部细节
- 降级策略明确：失败后是重试、换模型还是展示空态；自动重试必须有次数上限
- 网关 / 代理不可用时给出运维可排查的错误码或标识，并记录到文档

---

## AI 交互展示规范（与 frontend-AGENTS.md 配合）
- 消息列表区分用户 / 模型 / 系统提示；模型消息覆盖生成中 / 完成 / 失败 / 已中断四态
- 生成中提供停止按钮；失败提供可读原因与重试
- Markdown 与代码块渲染必须经过安全处理（sanitize / 白名单），禁止把未消毒内容直接注入 DOM（如 `innerHTML` / `v-html`）
- 输入区支持多行与快捷键发送，生成中禁用；必要时展示字数 / token 提示
- 页面状态覆盖 loading / streaming / empty / error，与 `design-system.yaml` 的页面状态规范一致

## 可选扩展能力规范（引入时再读）

> 以下能力默认不引入。只有当核心闭环已稳定、且出现明确需求时，按本节规范评估引入。

- **结构化输出 / function calling**：需要模型驱动界面动作时引入，工具 schema 集中定义在 `src/ai/`；模型给出的指令不直接执行，敏感动作需用户确认
- **本地向量 / RAG**：出现"对本地文档问答"需求时评估，先确认数据量、浏览器可行性（IndexedDB 向量方案）与成本
- **多模态（图片 / 语音）**：按 Provider 能力评估，注意产物体积、流量与浏览器兼容
- **多模型路由 / 降级链**：确有成本或可用性诉求时引入，路由策略集中在封装层

引入任何可选能力时：
1. 先在对应模块的 `doc/requirements/<module>/<feature>.md` 记录需求，并在 `doc/design/<module>/<feature>.md` 说明方案与影响
2. 评估对成本、延迟、复杂度的影响
3. 与用户确认后再实现，不默认扩大范围

## AI 安全与成本规范
- 密钥红线见上；网关侧配额、限流、审计按网关能力开启
- 关注 token 用量与调用频次；循环或自动重试必须有上限与可观测指标
- 用户输入与模型输出都需考虑注入与越权风险；模型生成的参数与指令仍需业务校验，不盲信

## 测试规则

### 提交前最小回归
- 默认执行：项目现有的静态检查、类型检查或构建校验
- 封装层改动：用 mock 流式响应验证一次输入输出与中断分支
- Prompt 改动：至少验证关键输出格式与边界（空输入、超长输入、异常输入）
- 交互组件改动：流式渲染、错误态、重试至少完成一次等价验证

<!-- include: shared/frontend/general-requirements.md -->

### AI 测试
- 单元 / 组件测试统一 mock 模型接口与流式事件，不真实调用第三方模型服务（避免成本、不稳定与隐私问题）
- 覆盖：流式中断、错误恢复、空响应、消息状态流转
- 真实模型验证作为补充手段，不计入自动化回归；调用真实模型时注意密钥与数据安全
