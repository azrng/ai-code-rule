# 后台管理端布局与页面模式

**使用场景**：新建或整理 Blazor 管理后台，需要统一主导航、页面层级、列表与编辑流程，同时保留项目品牌和设计系统的定制空间。

## 设计基线

- 后台是高频工作界面：优先保证信息可扫描、任务路径短、状态明确和操作反馈及时。避免营销式大标题、装饰性留白、无实际用途的卡片和过多动画。
- 颜色、字体、圆角、阴影、图标、间距和密度使用项目的 `design-system.yaml`、CSS variables 或现有主题。没有基线时先按产品品牌建立少量 token；不要在页面中散落硬编码颜色和间距。
- 复用 BootstrapBlazor 组件和项目已有组件；需要定制时先确认组件版本与现有封装，不混用其他 Blazor UI 库的参数。
- 页面区域保持清楚的层级。卡片用于确实需要分组的独立内容，不要把整个页面包进卡片后再在其中叠套卡片。
- 管理页优先沿用 BootstrapBlazor 组件表达页面结构和交互：列表用 `Card` + `Table<TItem>`，字段筛选与编辑用 `BootstrapInput` / `Select`，状态用 `Badge`，操作用 `Button`，短流程用 `Modal`。只有组件不适合表达的专有交互才使用原生元素或自定义封装。
- 使用 `Table<TItem>` 时通过 `TableColumns` 和 `RowButtonTemplate` 定义列与行操作；分页或筛选数据接 `OnQueryAsync` 并返回真实总数，避免用手写 `<table>` 加样式模拟组件行为。

## 应用壳层

| 区域 | 约定 |
| --- | --- |
| 主导航 | 按工作领域分组，标签简短一致；高频入口靠前，避免层级过深。当前页及其详情/编辑子路由应保持分组展开和入口高亮。 |
| 顶部区域 | 放置产品或项目标识、必要的全局动作和当前用户入口；全局动作数量有限，用户菜单承载个人设置、帮助或退出等低频操作。 |
| 主内容区 | 提供稳定的最大宽度或流式规则，避免页面间内容宽度无故变化；导航折叠后内容区应自然扩展。 |
| 页面标题区 | 标题说明当前对象或任务，可选副标题交代范围；主要动作靠近标题区，次要动作放入明确的操作菜单。 |
| 面包屑 / Tab | 仅在层级导航或多任务切换确有帮助时使用；当前页面标题仍需清楚，不让导航控件取代页面语义。 |

组件结构、菜单数据、活动路由、子路由展开和 Tab 参数见 `layout-menu.md`；本文不重复 BootstrapBlazor 参数示例。

## 常用页面模式

### 列表与搜索

- 标题与主要创建动作位于页面顶部；搜索和常用筛选紧邻数据表，筛选项按使用频率排序。
- 表格列优先展示决策所需字段；操作列稳定，批量操作仅在存在已选行时启用并明确作用范围。
- 使用紧凑但易读的行高、明确的列对齐和稳定的分页区。排序、筛选、页码变化应保留必要查询条件。
- 具体 Table、分页、搜索与行操作 API 见 `table.md`。

### 详情与编辑

- 详情页先展示识别对象所需的信息，再按业务关系分区；避免把完整实体字段不加筛选地铺在页面上。
- 简单且可取消的短操作可用 Modal；长表单、复杂校验、分步流程或需要深链接的内容使用独立页面。
- 表单按用户心智分组，必填项和校验错误贴近字段；保存中禁用重复提交，失败时保留输入并说明可操作的错误。
- 页面创建步骤与代码结构见 `crud-template.md`，表单和弹窗细节见 `forms.md`、`modal.md`。

### 用户、角色与菜单授权

- 用户管理页应清晰展示并维护用户绑定的角色；创建用户和调整角色都应使用服务端可分配角色目录。
- 角色管理页应展示成员数量和菜单授权概况；角色编辑时使用分组权限矩阵完成角色与菜单绑定。
- 导航可根据当前用户有效角色显示对应菜单，但页面、数据和操作仍需单独执行服务端授权。RBAC 约束见 `user-role-management.md`。

### 仪表盘与审计页面

- 仪表盘只呈现能引导下一步工作的关键指标、异常和待办；避免只有装饰性的数字卡片。
- 审计日志、历史记录和任务列表优先采用可筛选、可分页、可追溯的表格；详情按需展开。
- 对高风险动作，在动作附近明确对象与后果，并要求确认；成功或失败后提供即时结果反馈。

## 状态与响应式行为

- 加载中、空结果、加载失败、无权限和部分数据状态分别设计；不要用空白区域让用户猜测页面是否失效。
- 搜索无结果应保留筛选条件并提供清除入口；无权限应明确说明访问受限，不应伪装成空数据。
- 窄屏下侧边导航可折叠，筛选项换行或进入明确的筛选面板，表格按项目决策横向滚动或切换为摘要行；主要操作始终可找到。
- 键盘可访问导航、表格操作和弹窗；焦点顺序清楚，状态变化有可读反馈，不能只用颜色表达成功、警告或错误。
- 固定导航、固定表头和粘性操作栏需验证不会遮挡标题、焦点目标或窄屏内容。

## 页面实现前检查

- 确认产品品牌 token、导航信息架构、用户权限和目标视口，再套用页面模式。
- 用 `layout-menu.md` 确认 Layout / Menu / Tab API，用 `table.md`、`forms.md`、`modal.md` 和 `crud-template.md` 确认具体组件用法。
- 检查长标题、无数据、错误、无权限、窄屏、较长表格值和键盘操作状态，保证文案、按钮和内容不重叠或被裁切。
- 管理员可见的导航或按钮不代表后端已授权；授权边界按 `user-role-management.md` 执行。
