## 逐条判定

### 1. [2026-10-20] 代码评审委派子代理结论质量不稳定 —— 采纳（缺失）
- 原始场景：评审大提交并行派两个 general-purpose 子代理，第一轮 8 条「高危/中危」6 条误报（不存在的字段、已存在的 continue、未改动的断言）；第二轮 4 条全部属实。
- 落地：`shared/common/collaboration-AGENTS.md`「坦率反馈与过程沟通」新增一条——委派子代理 / 并行会话产出的评审结论按待验证假设处理，报告用户前逐条对照当前代码复核；委派提示词要求每条发现附当前代码行号证据；不按委派方严重度直接采纳，复核不通过不上报。
- 归属修正：反馈写「AGENTS.md 全局工作规则」，按根文件原则（根不放细则）落 collaboration。

### 2. [2026-10-28] Markdown 表格行号编辑反复损坏文档 —— 采纳（缺失）
- 原始场景：同任务 3 次行号编辑改 markdown 表格行，2 次因折叠显示与行号锚点错位损坏表格结构，均靠整文件重写修复，返工 2~3 轮。
- 落地：`shared/common/collaboration-AGENTS.md` 新增「文件编辑纪律」节——含 Markdown 表格的文件（TASK.md、需求 / 设计文档等）编辑前先读目标表格完整区域取最新锚点；改表格行优先整段（含表头分隔行）整体替换或整文件重写，不做跨折叠区域单行编辑。

### 3. [2026-11-24] 组件库迁移交付未走浏览器走查 —— 违反，规则本体不改，仅显式化触发面
- 原始场景：BootstrapBlazor→MudBlazor 迁移交付未走查，后任务发现 5 处样式静默失效（选择器优先级、类名不存在、`!important` 映射、图标丢失、logo 不可见）。
- 判定依据：`shared/ui/browser-walkthrough.md` 已有自含门控「界面交付前必须执行浏览器走查」，迁移属界面交付，违反是执行问题非文本缺口；选择器 / DOM 核对纪律 `shared/ui/blazor-scoped-css.md`（批次 42194af）已含「禁止以构建通过代替样式生效验证」。
- 预防性显式化（采纳一行）：门控句下新增一条——组件库迁移、主题或全局样式类任务同属界面交付，交付前走查不可省略；覆写组件库自带样式前先核对实际选择器优先级与真实 DOM 结构。封死「迁移不算界面任务」的判定歧义。
- 反馈自述教训已由目标项目同步进其 design-system.yaml usage_rules（项目侧定制面，无需仓库侧动作）。

### 4. [2026-11-25] HTML 原型缺少显式废弃流程 —— 采纳（缺失，本批价值最高）
- 原始场景：组件库迁移后 14 页 HTML 原型与实现脱节，同步门控仍压在每个界面任务上事实烂尾；用户拍板废弃整个目录；首轮引用扫描只扫 `prototype/` 路径漏扫 6 处「原型 NN」编号式引用（5 处为误导性活指令）。
- 结构性缺口：同步义务（原型与实现不一致时以原型为准）无终止路径。
- 落地：`shared/ui/prototype-workflow.md` 新增「原型废弃」节——两种触发情形（技术栈更换脱节、路线确认转沉淀型）经用户显式确认后废弃；废弃动作一次做全（目录删除 + 界面基线登记沉淀型路径 + 活引用全清，引用扫描覆盖路径引用与「原型 NN」编号式引用）；废弃后不留「以原型为准」空挂义务。`shared/doc/doc-directory.md` prototype 条目补一句指向。
- 反向语义检索：全量 grep「以原型为准 / 原型同步 / 未清理的 / 原型滞后 / 领先于原型」4 处命中，口径已逐一声明（prototype-workflow L12 / L50 管活原型，废弃节为经用户确认的出口；doc-directory 条目已带指向；collaboration 置 DONE 自检同口径）。

### 5. [2026-11-24] 共享文件按块暂存纯新增块落点偏移 —— 采纳（缺失）
- 原始场景：`git diff -U0` 筛块 + `git apply --cached --unidiff-zero` 暂存 TASK.md 纯新增行，因并行会话未提交的插入行位于本任务块上方，补丁新侧行号被顶偏一行；改用 hash-object + update-index --cacheinfo 落点正确。
- 落地：`shared/common/collaboration-AGENTS.md`「Git、验证与交付」——共享文件暂存条注明 add -p 仅交互式环境可用、无交互时直接走构造；-U0 筛块仅其他会话改动位于本任务块之下时可靠、对方插入行在上方时纯新增块按新侧行号落偏禁止盲用；构造清单新增第 4 条——构造完成后 `git diff --cached` 核对新增行落点与内容，不只核对内容出现。
- 不采纳细节：`--cacheinfo` 逗号写法属 git 版本细节不进规则。

### 6. [2026-11-25] 行为变更的置 DONE 自检不覆盖用户可见文案 —— 采纳（缺失）
- 原始场景：备份改明文免口令后 6 处用户可见说明未随行为更新（「加密备份」「口令用于创建备份」「电脑锁定将中断」「下轮自动清除」「即将重启」、写死的「0 条敏感条目」），跨 15 个任务才修复；原型同步同样漏（backup.html 保留旧设计帧）。
- 落地：`shared/common/collaboration-AGENTS.md` 置 DONE 自检条补一类触发面——行为或能力增删（机制废止、自动任务移除、计数口径、安全承诺变化）时 grep 旧关键词确认用户可见文案（界面、CLI、API 提示）无残留。`shared/ui/visual-acceptance.md` 补一条——界面文案与现状一致，只写用户可感知的行为与安全承诺、不含实现机制细节（线程、毫秒、原子操作、临时目录、内部文件名）。
- 文案照原型同步的部分既有条款已覆盖（置 DONE 自检后半句），不重复。
