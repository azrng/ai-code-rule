## 反馈判定（1/1 采纳）

### [2026-11-27] 缺少「界面文案克制」约定，自加说明性长文案被要求返工移除 —— 采纳（缺失）

- 原始场景：病案文件上传页（T294 / MR-MONTH-20261127）实现时，在状态卡副文案、上传面板底部、HQMS 配置弹窗、空态描述四处主动添加成句功能说明与政策复述（如「保存时服务端校验数据库连通性并自动创建域与两张表…」「同月各保留一份…确认后将覆盖原文件」）。用户明确反馈「界面不要加这种注释」，要求移除后返工。
- 根因：把后端校验规则、冲突覆盖政策、服务端行为直接复述到界面，源于「设计文档写了什么口径就展示什么」的错误倾向。规则层核实无对应约束——`shared/ui/visual-acceptance.md` 既有「界面文案与现状一致」只管验收时文案与实现一致，不管写界面时不自加说明段；各架构 `design-system.yaml` 的「Toast 文案简洁 15 字」是基线定制文件非硬规则且只覆盖 Toast。
- 归属判定（按变更归属表）：所有带 UI 组合通用 → `fragments/shared/ui/`（该目录片段被 100% 带 UI 组合 include：WPF / Avalonia / WinForms / MAUI / Flutter 桌面移动与全部 web 前端、混合壳），一处修改全部组合同步生效。不放反馈建议的 `backend-AGENTS.md`——界面文案不归后端子规则管。

## 落地

- `fragments/shared/ui/visual-acceptance.md` 新增「#### 界面文案克制」小节（置于主列表与「验证手段分层」之间）：
  - 写界面时即生效、不待视觉验收；界面只保留操作必需文案（按钮操作名称、字段标签、占位符、校验错误提示、状态结果含空态短引导与加载失败反馈）；未经用户要求不得添加成句功能说明 / 政策复述 / 实现机制描述，点名四个高发位置（状态卡副文案、面板底部说明、配置弹窗介绍段、空态长描述）。
  - 禁止把业务规则、覆盖 / 冲突政策、服务端校验与实现机制复述成界面说明段，引用反馈中两个原句作反例；设计文档 / 需求写了某口径不等于界面要展示，此类内容写设计与接口文档即可。
  - 不削弱既有口径：错误提示、空态引导、状态反馈照常按 `design-system.yaml` 基线与各子规则执行；用户明确要求说明性文案时按要求写并保持简短。
  - 与既有「界面文案与现状一致」互补声明：克制管要不要写说明段，一致性管已写文案与实现是否一致。
- 版本：manifest `vars.version` 3.25.0 → 3.26.0。
